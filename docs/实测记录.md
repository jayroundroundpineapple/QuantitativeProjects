# 实测记录 · 2026-11-16

这份文件记录**这一轮对话里跑出来的每一个数字**，以及它们是怎么来的。
目的是：半年后你自己（或别人）能判断"这个数字还算不算数"，而不是只看到一个漂亮百分比。

- 代码版本：`43f1638` + 本轮改动（财报因子开关、结果归档）
- 环境：macOS · Python 3 · akshare 1.20.65 · pandas 3.1.1 · numpy 2.5.5
- 回测区间：2021-01-01 → 2026-11-16（实际最后一个交易日 **2026-11-13**）
- 回测口径：月度调仓 · 月末收盘打分 · 次日开盘成交 · 涨跌停拦截 · 停牌跳过 ·
  100 股整手 · 佣金万 2.5 + 印花税千 0.5（卖出）+ 滑点千 1 · 初始资金 100 万

原始产物在 `results/`，每个目录里的 `metrics.json` 是这台机器写出的完整指标，
`nav.csv` / `trades.csv` / `holdings.csv` / `ranking.csv` 是逐日、逐笔明细。

## 1. 数据从哪来、新到哪一天

| 类型 | 接口 | 口径 | 本次最新到 |
|---|---|---|---|
| 行情 | 腾讯财经 `stock_zh_a_hist_tx` | 日线 · 前复权 | 2026-11-13 |
| 估值 | 百度股市通 `stock_zh_valuation_baidu` | 每日 PE(TTM) | 2026-11-13 |
| 财报 | 东财业绩报表 `stock_yjbb_em` | 季度 · ROE / 净利同比 / 行业 | 2026 三季报（10-31 起可用） |
| 退市名单 | 上交所 / 深交所公告 | 仅用于估算存活偏差 | 2026-11-16 |

**「是不是最新」要分三层，不能混为一谈：**

1. **源端延迟（改不了）。** 2026-11-16 16:00 直接请求腾讯接口核验：最新一根 K 线仍是
   11-13（上周五），当天周一的还没有。这是腾讯收盘后要 1–2 小时才发布，
   **不是本地缓存旧了**——那份数据是当场重新抓的。想拿到当日收盘价，晚上再跑一次。
2. **本地缓存（能改）。** 默认「复用本地缓存」时重跑不请求网络，看到的可能是上次抓的。
   要绝对值最新就关掉这个开关。判断方法：看「诊断」页数据来源表的最新日期，
   关缓存重跑后日期没变，那就是源端没更新。
3. **财报的会计延迟（故意保留）。** 因子按**法定披露截止日**生效（Q1 4/30、H1 8/31、
   Q3 10/31、年报次年 4/30），不是真实公告日，也不是表里的「最新公告日期」。
   宁可晚用，不可早用——早用就是未来函数。

## 2. 因子对照 2×2（本轮最重要的一个纠正）

同一批股票、同一个种子（42），**只切换「有没有财报因子」**：

| 模式 | 股票池 | 只有价值+动量 | 四因子齐全 | 差异 |
|---|---|---|---|---|
| both（多因子+轮动） | 97 随机 + 电网 3 只 = 100，可交易 59 | **11.06%** ／ -28.6% ／ IC 0.022 | **7.12%** ／ -32.9% ／ IC 0.010 | −3.94pp |
| factor（只跑多因子） | 纯 100 随机，可交易 69 | **4.37%** ／ -36.1% ／ IC 0.008 | **4.08%** ／ -36.7% ／ IC -0.002 | −0.29pp |

**结论一：补财报因子几乎不改变收益。** factor 模式同池对照只差 0.29 个百分点，完全落在噪声里。
早先"补齐因子后 11.06% 掉到 4.08%、亏 7 个点"的说法是**口径错误**——
11.06% 来自"97 随机 + 电网 3 只"的池，4.08% 来自"纯 100 随机"的池，两个池不一样。
差值不是因子造成的。

**结论二：池子里有没有那三只电网股，比用几个因子重要得多。**
同样只有价值+动量，11.06% 对 4.37%，**相差 6.7 个百分点**。三只股票就决定了四年的年化。

第 2 条是这个项目真正想说的：在 100 只这种样本量上，你测到的主要是「抽到了谁」，
不是「方法好不好」。

> 记账错误也是数据的一部分。上面这个错是这一轮自查时发现的，原样留在文档里，
> 因为它比"结论正确"更能说明为什么要做对照实验。

## 3. 抽样压力测试：不换参数，只换股票

从 400 只母体里反复抽 100 只、持仓 20 只、`mode=factor`、抽 12 次：

```
年化   中位 +1.85% ｜ 均值 +2.78% ｜ 中间 80% 区间 -1.29% ~ +9.00%
       最差 -2.74% ｜ 最好 +10.74% ｜ 标准差 4.22pp
超额   中位 +1.62% ｜ 12 次里 8 次跑赢基准（67%）
回撤   中位 -34.7% ｜ 最差 -42.2%
夏普   中位 0.07
IC     中位 -0.009
```

怎么读：

- **单次的 7.12% 是运气偏上的那一次。** 同一套规则换批股票，年化能横跨 13.5 个百分点。
- **超额中位 +1.6%/年，却要扛 -35% 的回撤**，赔率完全不成立。
- 这是**下界**：母体只有 400 只，真实全 A 股（5000+）的抽样波动只会更宽。
- IC 中位 -0.009 ≈ 0，说明打分和未来收益之间**在这个样本上关系为零**。

## 4. 电网设备轮动

| 配置 | rotation | sector_only（死拿三只） | 当前信号 |
|---|---|---|---|
| 两因子池 | 25.89% ／ -32.1% ／ 夏普 0.88 | 16.60% ／ -41.4% ／ 夏普 0.51 | 强度分 **-0.20** → 回到全市场 |
| 四因子池 | 13.94% ／ -35.3% ／ 夏普 0.48 | 16.44% ／ -41.4% ／ 夏普 0.50 | 同上 |

`rotation` 在强度分为负的月份会退回去持有多因子组合，所以它会随因子集变化——
两因子池 25.89%、四因子池 13.94%，差的那 12 个点来自"空仓期"改持什么，不来自轮动信号本身。
`sector_only` 几乎不变（16.60% vs 16.44%），因为它压根不看因子。

**这组数字不能信。** 3 只股票、约 60 个月、1 个阈值（阈值还是事后挑的），
自由度为零的检验都做不了。夏普 0.88 不等于策略有效，等于样本太小。

## 5. 存活偏差

```
样本 100 只全部活到今天；其中 36 只是 2021 年以后才上市（回测早期根本没得选）
区间内暂停/终止上市 228 只 ／ 现存 5579 只 → 退出率 3.93%
估算等权基准年化虚高 0.57 个百分点
```

这是本次**唯一方向明确、量级可复现**的数字。口径是"暂停、终止上市"名单，
属于上限估计；真实偏差只会更大（不含被并购、主动退市、长期停牌后摘牌）。

## 6. 怎么复现

```bash
# 服务
python3 app/server.py --port 8770 --no-open

# ① 四因子 · both · 97+3
curl -X POST localhost:8770/api/run -H 'Content-Type: application/json' -d \
 '{"pool":"sample","n":100,"start":"2021-01-01","end":"2026-11-16","top":20,
   "mode":"both","seed":42,"cost":true,"use_cache":true}'

# ② 两因子 · both · 同池对照（加 "fundamentals":false）
# ③ 四因子 / ④ 两因子 · factor 模式（把 "mode" 改成 "factor"）

# ⑤ 压力测试
curl -X POST localhost:8770/api/stress -H 'Content-Type: application/json' -d \
 '{"pool":"sample","n":100,"top":20,"mode":"factor","seed":42,"draws":12,"pool_size":400,
   "start":"2021-01-01","end":"2026-11-16"}'

# 把某次产物归档到 results/
python3 tools/collect_results.py <job_id> <目录名> [--html]
```

同一台机器、同一份缓存下，上面四条 `run` 会**精确复现**表里的数字
（本轮已验证：`fundamentals=false` + both + seed42 = 11.06% / 25.89%，与改动前逐位一致）。

## 7. 本轮改了什么

| 改动 | 为什么 |
|---|---|
| `fundamentals` 开关（后端 + 界面「执行假设」） | 让"两因子 vs 四因子"能在**同一个池**上对照，否则永远是两个变量一起动 |
| `results/` 归档 + `tools/collect_results.py` | 之前的产物在 `.gitignore` 里，数字无法被检验 |
| 纠正 11.06→4.08 的对比口径 | 原结论混了股票池，见第 2 节 |
| 历史记录优先展示多因子指标 | 压力测试任务没有 `lines`，副标题会空 |
| 端口探测加 `SO_REUSEADDR` | 刚退出的进程留 TIME_WAIT，会误判 8770 被占而顺延到 8771 |

## 8. 还没解决的

- **tushare 适配器未实测。** 本机没装 `tushare`、也没配 token，`src/tushare_source.py`
  里的字段映射与复权计算**只做过静态检查**。要用它治存活偏差，得先 `pip install tushare`
  并 `export TUSHARE_TOKEN`，再跑 `python3 -m src.tushare_source --check`。
- **PIT 是近似的。** 用法定披露截止日代替真实公告日，对绝大多数股票一致，但会晚几天到几周。
  严格做法是存每日快照。
- **存活偏差仍在。** 免费源只有"今天还活着"的股票，0.57pp 只是估算，不是修正。
- **样本量。** 100 只、5 年、3 只轮动标的——所有结果的统计功效都接近零。
  这不是靠调参能解决的，只能换全样本 + 更长区间。
